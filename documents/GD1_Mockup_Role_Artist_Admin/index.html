2. Quy tắc nghiệp vụ

  • Chỉ tài khoản listener mới thấy nút đăng ký. Tài khoản đã là artist hoặc admin thì không.
  • Mỗi tài khoản chỉ có 1 yêu cầu đang chờ. Muốn sửa nội dung thì huỷ yêu cầu rồi gửi lại.
  • Người dùng luôn tạo trang nghệ sĩ mới. Nghệ danh không được trùng với trang đã có hoặc với yêu cầu khác đang chờ. Khi so trùng, hệ thống bỏ qua khác biệt chữ hoa/thường và có dấu/không dấu.
  • Khi Admin duyệt, hệ thống làm cùng lúc 4 việc (nếu một việc lỗi thì không việc nào được lưu):
    • tạo trang Artist mới từ hồ sơ;
    • gán ownerUserId của trang là tài khoản người gửi;
    • đổi tài khoản sang role = artist và gán artistId;
    • gửi thông báo cho người dùng.
    Trang mới mặc định chưa có tick xanh; Admin có thể bật khi duyệt. Người dùng không cần đăng nhập lại.
  • Khi Admin từ chối: bắt buộc chọn lý do; nếu chọn "Other" thì bắt buộc ghi thêm. Người dùng thấy lý do, sửa hồ sơ rồi gửi lại.
  • Admin dùng chung app: đăng nhập như người dùng thường, vẫn nghe nhạc bình thường; Profile có thêm thẻ "Admin console". Server kiểm tra role = admin ở từng API admin, nên tài khoản thường không gọi được dù tự sửa app. Admin đầu tiên được tạo bằng script npm run make-admin -- <email>; trong app không có nút "đăng ký admin".

5. Phần sẽ làm khi hiện thực (sau khi duyệt mockup)

Hạng mụcChi tiết
Dữ liệuModel mới ArtistRequest: userId, stageName, genres, bio, avatarImage, socialLinks, status (pending/approved/rejected/cancelled), rejectReason, rejectNote, reviewedBy, reviewedAt, createdArtistId. Notification có thêm loại artist_request_approved và artist_request_rejected.
API cho appPOST /api/artist-requests (gửi), GET /api/artist-requests/me (trạng thái), DELETE /api/artist-requests/me (huỷ), POST /api/artist-requests/avatar (tải ảnh đại diện).
API cho Admin
  • GET /api/admin/summary
  • GET /api/admin/artist-requests?status=&q=&page=
  • GET /api/admin/artist-requests/:id
  • POST …/:id/approve { verified }
  • POST …/:id/reject { reason, note }
Tất cả dùng requireAuth + requireRole('admin'). Thao tác duyệt chạy trong transaction, nên không có trường hợp đổi role mà chưa tạo trang.
Scriptnpm run make-admin -- <email>: nâng một tài khoản có sẵn lên admin.
AppMàn hình mới:
  • Người nghe: ArtistRequest (A2–A3, 2 bước), ArtistRequestStatus (A4, A5), StudioComingSoon.
  • Admin: AdminConsole (B2), AdminRequests (B3), AdminRequestDetail (B4–B6).
AuthContext thêm isArtist và isAdmin; AccessContext thêm ensureArtist và ensureAdmin; sửa Profile (A1, A4b, A6, B1) và NotificationsScreen.
Kiểm thửUnit test cho kiểm tra form và quy tắc chuyển trạng thái. Integration test cho:
  • gửi yêu cầu, gửi khi đang có yêu cầu chờ (bị chặn), huỷ yêu cầu;
  • nghệ danh trùng (bị chặn);
  • duyệt: role, trang nghệ sĩ và thông báo cùng được tạo;
  • từ chối mà không có lý do (bị chặn);
  • tài khoản không phải admin gọi API admin (403);
  • hai admin cùng duyệt một yêu cầu (chỉ lần đầu thành công).
